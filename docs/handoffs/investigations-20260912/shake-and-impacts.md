# Investigation: shake-and-impacts

Camera shake is a projection-only render-container offset: four call sites feed `triggerCameraShake(tick, magnitude)` (apps/hmh-reboot/src/main.mjs:1302-1308) with weapon recoil 0.9-7.5 from `WEAPON_RECOIL_SHAKE` (combat-feedback.mjs:21-35, call at main.mjs:3844), player hit 5 (main.mjs:4265), grenade blast 8.5-10 x radius cap 1.2 via `grenadeBlastShake` (grenade-feedback.mjs:27-30,91-97; call main.mjs:4005) and boss death 12 (main.mjs:4281); the offset is applied at main.mjs:4741-4750 gated only by the boolean `settings.screenShake && !settings.reduceMotion` with a 9-tick linear decay (SHAKE_DECAY_TICKS main.mjs:285) and no intensity or tier concept anywhere. `screenShake` is a required boolean on the bridge (sdk/hmh-bridge-protocol.mjs:50-57), persisted by the portal under localStorage 'hmh-settings' as `gameplay.screenShake` in the version-1 nested schema (apps/portal/src/hmh-player-settings.mjs:3,28,71,123,150; main.js:1035,1045,1057), toggled in the child pause panel through the boolean-only `PAUSE_SETTING_KEYS`/`applyPauseSetting` path (main.mjs:1186-1222, cockpit-ui.mjs:44-49,136-148, index.html:163-166) while the numeric `sfxVolume` already rides a separate `applyPauseLevel`/`onSettingLevel` slider path (main.mjs:1227-1233, cockpit-ui.mjs:150-169, index.html:176-184) that is the exact template for a shake slider. Ranked play locks only keyboardBindings (hmh-player-settings.mjs:95-102,113; main.mjs:1188-1189), so a projection-only intensity value would not be locked; no 'save schema 2' exists for settings (HMH_PLAYER_SETTINGS_VERSION = 1; the only schemaVersion 2 values are the hero atlas and long-run simulator, unrelated). Impact surfaces are already five classes ['flesh','dirt','rock','metal','water'] (weapon-vfx.mjs:24) resolved by `classifyImpactSurface` (weapon-vfx.mjs:171-189): every target hit is hard-coded 'flesh' (main.mjs:3788 burner, main.mjs:4246-4260 all combat damage events including the boss and the player), cover hits map blocker `visualKind` via COVER_SURFACE (cliff->rock; containers/machinery/bridge-rail/building->metal; fence and dense-trees fall through to dirt), and range-expired shots classify from the ground query + DISTRICT_TERRAIN_MATERIAL (main.mjs:3641-3654, terrain-tile-atlas.mjs:20-27). The live world has exactly seven blocker visualKinds (cliff 8, fence 27, containers 7, machinery 10, dense-trees 11, building 16, bridge-rail 4; LEVEL_ONE_WORLD.blockers enumerated read-only), so 'wood' and 'armor' are absent as classes even though enemies carry `armor` (enemy-archetypes.mjs:28-123, whale-enforcer 1.35) and `archetypeId` on the runtime record (enemy-simulation.mjs:133,149) and the damage event carries `shielded` (combat-events.mjs:132-158) which only tints the ring blue and suppresses gore (weapon-vfx.mjs:221,230).
