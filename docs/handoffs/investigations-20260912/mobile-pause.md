# Investigation: mobile-pause

On phones (<=720px) the pause-menu jukebox is forced into normal flow by styles-arcade-polish.css:1212-1217 (`.arcade-music-player { position: static; width: 100%; margin: 10px 0 14px }`), which wins the specificity tie against the base `position: fixed` (styles.css:2530) because polish loads after styles.css (index.html:50-54); none of the pause-deck rules (styles.css:2554-2561, 2804-2814, 2845-2852) re-assert `position`, so their left/right/top/bottom offsets are no-ops. The static deck still stacks at z 10030 because it is a flex item of `.official-app` (styles.css:177-181, `display:flex; flex-direction:column`) and Flexbox lets a static flex item's z-index create a root-level stacking context; that outranks `#officialGameplay` (`.official-view` z 1, styles.css:346-348), which scopes both the fixed pause icon button (z 99, styles.css:3545-3554) and `#combatMenuPanel` (z 10020, styles.css:4984-4995). Probe-measured on 390x844 while paused: expanded deck occupies 16..374 x 26..441 in flow (pushing the game view down, docH 966->1329) and the collapsed launcher, dragged to the right edge by `transform: translateX(calc(100vw - 88px))` (styles.css:2809), sits at 318..370 x 26..78; both cover the icon button's click point (354,36). E2E reality (reproduced, evidence in scratchpad): guest-free-run fails on renderer liveness (line 292-297), pause-resume fails at the audio wait (line 418-422: jukebox is already playing at pause on BOTH profiles, so the 'play' click pauses it; reboot pause branch main.js:3680-3689 never calls pauseCombatMusic) leaving the game paused with the deck expanded, and only then do mid-run-restart / settings-persistence-reload fail with 'aside#arcadeMusicPlayer intercepts pointer events' on openPauseMenu (line 307-310); guest-exit-to-splash cascades from that. Fix is CSS-only in styles.css (0 B HMH JS budget): make the pause deck fixed again with margin 0, dock the collapsed launcher under the 44px icon button instead of over it, and cap the expanded drawer so it never climbs into the top strip. Character select: desktop hides the jukebox at polish:1976-1980 (hero smoke line 139 holds); on phones it is in flow with zero overlap against all four hero cards (probe), unaffected by this fix since it targets `[data-surface="pause-menu"]` only.

## Root cause
Two-layer CSS defect, phone-only (<=720px), verified with a Playwright probe (computed styles, rects, document.elementsFromPoint) on 390x844 isMobile/hasTouch. (1) Cascade: apps/portal/styles-arcade-polish.css:1212-1217 inside `@media (max-width: 720px)` sets `.arcade-music-player { position: static; width: 100%; max-width: none; margin: 10px 0 14px; }`. It has the same specificity (0,1,0) as the base `.arcade-music-player { position: fixed; ... }` at styles.css:2529-2541 and the polish sheet is linked later (index.html:50-54), so on phones the jukebox is static in every state. The pause-deck rules `.arcade-music-player[data-surface="pause-menu"]` (styles.css:2554-2561), the collapsed launcher (2804-2814) and the expanded drawer (2845-2852) set right/left/top/bottom/width but never `position`, so those offsets are ignored and the deck is laid out as an in-flow child of `#officialApp.official-app` ahead of every routed view (index.html:103). Probe: computed position 'static', top 'auto'/'20px', deck rect expanded 16..374 x 26..441 (adds 415px of flow height: documentElement.scrollHeight 966 -> 1329 while paused), collapsed 318..370 x 26..78 (the 52px circle is dragged to the right edge only by `transform: translateX(calc(100vw - 88px))` at styles.css:2809). (2) Stacking: `.official-app` is `display: flex; flex-direction: column` (styles.css:177-181). Per CSS Flexbox 4.3 a flex item's `z-index` other than auto creates a stacking context even when `position: static`, so the deck's `z-index: 10030` (styles.css:2557) puts it in the ROOT stacking context above `#officialGameplay` (`.official-view { position: relative; z-index: 1 }`, styles.css:346-348). `#combatMenuIconButton` (`position: fixed; top: max(14px, env(safe-area-inset-top)); right: max(14px, ...); 44x44; z-index: 99`, styles.css:3545-3554; rect 332..376 x 14..58, center 354,36) and `#combatMenuPanel[data-state="paused"]` (`position: fixed; z-index: 10020`, styles.css:4984-4995; rect 14..376 x 14..830) are both descendants of `#officialGameplay`, so their z-indices are scoped inside z 1. elementsFromPoint(354,36): expanded -> [aside#arcadeMusicPlayer, p.eyebrow, div#combatMenuPanel, svg, button#combatMenuIconButton]; collapsed -> [button#arcadeMusicExpandButton, .arcade-music-controls, aside#arcadeMusicPlayer, p.eyebrow, div#combatMenuPanel]. Playwright therefore reports 'aside#arcadeMusicPlayer intercepts pointer events'. Trigger chain in scripts/hmh-reboot-portal-e2e.mjs --profile=mobile (reproduced, PORTAL_E2E_EVIDENCE_DIR redirected to the scratchpad): guest-free-run fails first on `assertRendererAnimating` (line 292-297, 'rendered child frame did not change while running'; unrelated to the deck). pause-resume opens the menu (paused), expands the deck (388), then fails at 418-422: the jukebox is ALREADY playing when paused (probe on both profiles: data-playing='true', audio.paused=false, because startArcadeMusicForGame autoplays at run start and the hmhRebootActive branch of toggleCombatPause main.js:3680-3689 does not call pauseCombatMusic), so `page.click('#arcadeMusicPlayButton')` toggles it OFF and the 15s waitForFunction for a playing track times out - identical on desktop, matching the known desktop pause-resume failure. That leaves the game paused with the deck expanded. mid-run-restart and settings-persistence-reload then call openPauseMenu() (307-310) which clicks the now-'Resume game' icon button under the expanded deck -> intercept -> 30s click timeout; guest-exit-to-splash times out waiting for #officialWalletSplash because the page is still in gameplay. Even with the deck fixed, the icon button stays under the pause sheet on phones (probe with the fix injected: interceptor becomes `p.eyebrow` of #combatMenuPanel), which is why the e2e already resumes via `#combatMenuActionGrid [data-action="resume"]` on mobile (446); the cascade can only go green once pause-resume's audio step passes. Desktop is unaffected because the polish static rule is gated to <=720px. Character select: desktop hides the jukebox via polish:1976-1980 `@media (min-width: 701px) #officialApp[data-step="character-select"] .arcade-music-player { display: none }` (hero smoke line 139 passes); on the mobile profile the jukebox is in flow above the roster (rect 16..356 x -172..-30 after scroll) with 0 overlap against all four hero cards, so no equivalent defect there - it only contributes ~166px to the pre-existing 1866px document height (smoke line 128 guard).

## Proposed change
CSS-only, apps/portal/styles.css, three edits (no JS, no index.html, no polish changes). A) styles.css:2554-2561 `.arcade-music-player[data-surface="pause-menu"] { ... }`: add `position: fixed;` and `margin: 0;`. Specificity (0,2,0) beats polish:1212's (0,1,0) so the pause deck is a fixed overlay again on phones (the offsets in the phone rules become live), and `margin: 0` cancels polish's `margin: 10px 0 14px` that otherwise shifts the fixed box (probe showed launcher top 76 instead of 66 without it). Scoped to data-surface='pause-menu' (set only when officialAppStep==='gameplay' && combat.paused, main.js:1116/1124), so mode-select / character-select / splash keep the in-flow phone layout. B) styles.css:2804-2814 (collapsed launcher inside `@media (max-width: 720px)`): replace `right: 20px; top: 20px; bottom: auto; left: auto; transform: translateX(calc(100vw - 88px));` with `top: calc(max(14px, env(safe-area-inset-top)) + 52px); right: max(14px, env(safe-area-inset-right)); bottom: auto; left: auto; transform: none;` keeping width/height 52px, padding 3px, overflow hidden, border-radius 50%. The translateX existed only to drag a static box to the right edge; with fixed positioning it would push the launcher ~302px off-screen. Docking 8px under the 44px icon button (14+44+8=66) keeps the e2e envelope (launcher 52x52 at x 324..376 >= 310, y 66 <= 80) and removes the overlap with the button (bottom 58). C) styles.css:2845-2852 (expanded drawer): change `max-height: calc(100dvh - 16px)` to `max-height: calc(100dvh - 80px)` and add `top: auto;` so the bottom-anchored drawer (left/right/bottom 8px, overflow-y auto, queue 20dvh) can never climb into the 66px top strip even with a long queue or a short phone; probe result 8..382 x 407..822 with all 8 controls >=44px, inside the viewport and inside the deck, drawer still overlapping the pause sheet (mobile e2e asserts overlapArea > 0), and no layout shift (documentElement.scrollHeight 890 in both states vs 966/1329 today).
