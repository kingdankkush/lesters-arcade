# Ranked entry fee 0.1 -> 0.01 zkLTC (0.012 zkLTC per run): hand-over, 2026-09-26

**Owner decision (2026-09-26):** the Ranked entry fee moves from 0.1 zkLTC to **0.01 zkLTC** per run. The LiteForge faucet now gives 0.05 zkLTC per request, and 0.1 zkLTC was about $7.31 at that day's Litecoin price. The settlement gas reserve stays **0.002 zkLTC** (it pays the relayer's gas: about 475k gas per settlement at about 1.5 gwei), so a run totals **0.012 zkLTC**. The 85/15 split does not change: 0.0085 zkLTC to the game's developer and 0.0015 zkLTC to the treasury per run.

**Branch:** `fable/ranked-fee-001` from `fable/master-list-20260916` at `32018fbd`. Nothing here sends a transaction or touches a key; the on-chain change belongs to the pre-deploy session (below).

## Release order (binding)

1. **Ship this branch first.** It lowers the server's settle floor, `DEFAULT_MIN_PAID_WEI` in `server/config.mjs`, from `102000000000000000` to `12000000000000000` (contract A27; `server/settle/settle-core.mjs` refuses a run whose paid amount is below it with `402 entry-underpaid`). Production does not set `RANKED_MIN_PAID_WEI`, so the default is the floor. Runs paid at the old 0.102 zkLTC still clear a 0.012 floor, so nothing in flight is refused.
2. **Then the pre-deploy session sends the three `GameRegistry.setEntryFee(gameId32, 10000000000000000)` transactions** (one per game: `lester-blaster`, `chikun`, `stacked`) from the operator wallet `0x6Ac08Bed727A6951D755F0674f096E6A8AC06bfF`, with the owner's approval. `node scripts/operator-actions.mjs entry-fee 10000000000000000` plans them and refuses a fee whose total (fee + the on-chain reserve) is below this checkout's floor; `--broadcast --confirm SET_ENTRY_FEE_4441` plus the operator key sends them. `ArcadeRankedEntry.quoteEntry` then returns 0.01 + 0.002 = 0.012 for every game.
3. **Never the reverse.** A 0.012 run settled by a server still on the 0.102 floor is refused after payment.

Until step 2 lands, the Ranked modal shows the client constant in its Entry row (0.01) while the reserve and total rows follow the live quote (0.002 and 0.102): a visible mismatch for that window only. The runtime price path stays quote-driven (the player pays `quoteEntry().totalWei`; `main.js` is unchanged here), and the ranked-onboarding slice renders the whole breakdown from the live quote.

## Weekly $CHIKUN Jackpot: what the 10x smaller fee changes

- **Funding: nothing.** Pots are funded only by $CHIKUN deposits (`minFundWei` is 100 tCHIKUN in token units); no share of the entry fee ever flows into a pot. No fixture, contract or server number derives a pot from the fee.
- **Eligibility: everything, on the deployed testnet instance.** The jackpot rules carry `minPaidWei` (J17), and the deployed 2961 epoch (`contracts/deployment-record.jackpot.json`) was created at 0.1 zkLTC, the flat fee at the time. Rules are immutable per week, so once `setEntryFee` lands, a 0.012 run pays less than that minimum and **no run qualifies** there; the portal's entry-modal jackpot row hides itself for that reason (`showEntryJackpot` compares the quote with `minPaidWei`), and the server selection excludes such runs.
- **Owner decision 2026-09-26: the jackpot is on hold until mainnet, so no action now.** The mainnet instance must be deployed with `minPaidWei` equal to the fee in force then (`--rules launch` now derives it from `LAUNCH_MIN_PAID_WEI`, pinned to the client fee by `tests/ranked-fee-source-of-truth.test.mjs`; `scripts/deploy-weekly-jackpot.mjs` warns when the on-chain fee and `minPaidWei` differ), or its rules are rescheduled on a Monday boundary with `schedule-rules`. Reviving the testnet instance would need exactly that owner-approved `schedule-rules` transaction; not done here.
- Fixtures left unchanged because they mirror the deployed instance or the server filter, not the fee constant: `tests/fixtures/jackpot/*.json` (rules `minPaidWei` 0.1), `tests/fixtures/jackpot-server/helpers.mjs` (`MIN_PAID_WEI`, seeded `entryAmountWei` 0.102), `tests/jackpot-server-select.test.mjs`, `tests/jackpot-server-screen.test.mjs`, `tests/jackpot-ui-surfaces.test.mjs` (they exercise "quote below / at / above `minPaidWei`" with realistic 0.1 rules). `tests/weekly-jackpot-contract.test.mjs` and `tests/jackpot-deploy-tooling.test.mjs` deploy the local suite from the deploy config, so they now run at 0.01 and are repinned.

## Relayer economics

Healthy. Each run brings the 0.002 zkLTC reserve to the relayer vault; a settle costs about 0.0001 zkLTC at 0.22 gwei (about 0.0007 zkLTC at the 1.45 gwei peak), so the reserve still covers every settlement with margin. `/api/health` keeps reporting the relayer balance and the estimated settlements left.
