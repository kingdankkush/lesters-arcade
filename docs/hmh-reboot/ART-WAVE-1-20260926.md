# Art wave 1 (2026-09-26): the Liquidator pilot and what it proved

Branch `fable/hmh-art-wave1` from the 1.8.4 receipt head `9f20cda0`.
Asset, manifest and projection only. Nothing in this wave touches collision,
hurtboxes, damage, AI, spawning, RNG, progression, evidence, results or any
simulation module; `main.mjs` is untouched. Casting decisions live in
`design/CASTING-DECISIONS-20260926.md`; every Tripo task is in
`TRIPO-SPEND-LEDGER.md`.

no actions, so the procedural poser drives every clip either way.

## 3. What the exporter contract had to learn

- **Camera.** The package (4.1, 5.10, section 6) puts new actors on the hero
  camera at 35 degrees below the horizon with `hmh-light-rig.json`. The shipped
  heroes and the core six still render at 55 degrees (their manifests say
  `cameraPitchDegrees: 55`; `create-hmh-production-hero-pilot.py` derives the
  camera height from it), so until the S4.8 re-render lands the Liquidator is
  the only 35 degree actor in the world. That is the package's own sequence,
  recorded here so nobody reads the mixed cameras as a defect of this pilot.
- **Light rig.** `lightRigFamily: hero` uses the shared colours with the hero
  energies (560 / 340 / 480). Under that key a lit `#ff496c` base clips to
  pink-white in AgX. The accent is therefore emission-led: base dimmed to 0.18
  of the accent, emission strength 0.7 (2.0 still desaturated), and the
  exporter's per-phase recolour multiplies the base by `hmh_accent_base_scale`
  so the dimming survives the phase swap. The ring reads crimson-salmon; the
  constants are in one place in the derivative builder if the owner wants it
  deeper.
- **Frame size and ortho.** 192 px frames as the shipped boss. The ortho is
  the size knob (the exporter normalises every derivative to 1.75 m and the
  boss's build lives in `cameraOrthoScale`, exactly as the procedural roster
  manifest does). Measured, not tuned by feel: see section 4.
- **Textures.** The roster path renders the Tripo PBR set (colour, normal,
  ORM) straight under the shared rig like the shipped five; the external
  pipeline's `HMH_LookDev_v1` band shader and waist split are hero-pipeline
  features (layered atlases) and were not applied because the roster renders a
  single body layer. The pipeline doc's C-1 limitation (packed textures counted
  as external dependencies) lives in the hero runner and did not bite here.

## 4. The size cap, measured

The design asks for about 2.4 m, 90-95 world px (about 1.8x an ordinary
enemy). The current single-page contract cannot hold that:

| Ortho | Idle body height (192 px frame) | World px (x0.86) | 840 padded frames | Lossless WebP (measured ~1.0 byte per sprite pixel) | Fits one 2048 page? |
|---:|---:|---:|---:|---:|---|
| 3.5 | 89 px | 77 | 5.08 M px | ~4.8 MB | no (page 4.19 M px, cap 4 MiB) |
| 3.8 | 82 px | 70 (today's shipped boss) | 4.33 M px | ~4.1 MB | no |
| 4.1 | 76 px | 65 | 3.75 M px | ~3.75 MB | edge to edge |
| **4.15** | **76 px (packed)** | **65** | 3.60 M px sprite area, page fill 0.908 | **3,007,902 bytes** (0.835 byte per sprite pixel) | **yes, 2048 x 1936** |

The shipped Bagholder-body boss packed 840 frames at 89 percent of the page;
the human body at 35 degrees is taller per frame and wider at the tell, so at
the same ortho it no longer fits. The pilot therefore ships him about 9
percent under today's world size (64 versus 70.5 world px; 1.26x the shipped
Bagholder's 50.5). The design size needs the boss-schema extension the package
assigns to the Baron slice (4.1: about 1,100-1,200 frames, reduced re-baked
phase 2/3 subsets, one resident boss atlas with an unload path, a 128 px
mobile tier). Reduced phase 2/3 subsets alone were measured too: 584 frames
fit at ortho 3.4-3.5 (about 77 world px) but break the 840-frame pins in
`hmh-native-roster-adoption.test.mjs`, `hmh-reboot-enemy-roster-atlas.test.mjs`
and `hmh-reboot-production-asset-qa.mjs` plus the fixed clip counts in four
pipeline scripts, so they belong with that extension, not with a projection
swap.

Roster wire budget after the swap: 14,892,353 bytes (14.2 MiB) of the 16 MiB
`maxRosterAtlasTotalBytes`, down from 15,155,687 with the shipped boss
(`npm run assets:qa:hmh-reboot`: pass). Decoded page 2048 x 1936 x 4 =
15,859,712 bytes (15.1 MiB), against 16,646,144 before; native decoded total
66,322,432 bytes.

## 6. Deviations from the step brief, stated

- **Clips.** Six states per phase (idle, run, tell, attack, hit, death), the
  runtime's pinned set. The 4.3 boss clips (dash, the three tell variants,
  halt, kneel, intro, transitions) need the roster-schema extension before an
  atlas can carry them; authoring them now would render frames no code can
  select.
- **Phase dressing.** Phase 2 adds gold margin spikes on the epaulettes, phase
  3 adds the violet halo; both recolour the crown band. "Coat off" and "tie
  torn, crown cracked" are mesh edits on a single Tripo texture set and were
  not attempted as accessory swaps.
- **Gavel.** Authored Blender primitives on `weapon_socket` (steel head, brass
  caps, wrapped handle, head-up in the right fist), not a 40-credit prop
  generation: the casting doc keeps simple mechanical props as primitives and
  nothing of a textured hammer survives a 20 px head.
- **Mobile tier.** No 128 px tier was rendered; the runtime has no tier
  selection and the boss is not a new enemy under the 5.10 gate. The decoded
  page is measured above.
- **Blind read.** The casting doc's two-session blind read of the head crop
  is still owed; this workflow is non-interactive.

## 9. Browser review of the live swap (2026-09-26, pilot closeout)

Harness: `scripts/hmh-liquidator-browser-review.mjs` (committed). It serves
the built child from `apps/portal` on 127.0.0.1:8913, loads
`?telemetry=1&evidenceSafe=1&boss=1&rosterPreview=1`, waits for
`data-boss-art=production-roster-atlas-v1`, walks the hero to a stand-off and
samples a screenshot plus stage telemetry every 2.5 s until simulation tick
3,000. It runs at desktop 1440x900 (DPR 1) and phone 390x844 (DPR 2, touch).
One background command acquired the heavy lock, started the server, ran the
review, killed the server and released the lock (`trap` on EXIT), so an
interrupted agent cannot strand the lock.

It took three runs. The first two failed because of harness defects, not art
defects:

| Run | Stand-off | Result | Lesson |
|---|---|---|---|
| 1 | 190 px due south of the boss | assertions passed, but the boss sat **behind the top HUD** in every frame (only his boots showed at desktop; nothing at phone). The green run proved nothing | a telemetry pass is not a visual review; compute where the actor lands on screen before trusting frames |
| 2 | south-west, clear of the HUD at the measured boss-fight zoom (desktop ~1.9, phone ~1.4) | boss fully visible, but the unarmed hero (`rosterPreview` disables auto fire and auto dodge) **died at tick 2,326 / 2,161**. The simulation froze, 28 identical frames followed and phase 3 was never reached | stop sampling at death; the review hero needs an evasion policy |
| 3 | same stand-off, plus scripted evasion and held-key movement. The evasion reads only public telemetry (`bossPendingAttackIds`, `bossSafeSector`). The boss holds the debug spawn, and the evasion geometry mirrors `LIQUIDATOR_ATTACK_DEFINITIONS` | **PASS**: 100 health throughout, all three phases on both profiles. States idle, tell and attack seen. Zero page errors, zero request failures, no roster load error, no horizontal overflow | |

Run 3 evidence (committed as lossy WebP evidence sheets):

- `docs/testing/hmh-native-roster/the-liquidator/browser-review/boss-crops-desktop.webp`: 16 samples, ticks 164-3,024.
- `boss-crops-mobile.webp`: 19 samples, ticks 172-3,141.
- `scenes-phase2-phase3.webp`: a margin-call tell and a total-liquidation frame per profile.
- `review-summary.json`: every sample's telemetry and every evasion.

The full-resolution PNGs stay under `.hermes/evidence/liquidator-browser-review*`
(ignored by Git).

Findings, read at full resolution and at 2x crop:

- **He reads as a human executive at both sizes.** At desktop the pale dome,
  red lapels, gold epaulettes, dark double-breasted coat, gloves, boots and
  gavel all read. At the phone the silhouette, lapels, gavel and head read,
  but the face does not (expected at about 90 device px).
- **Tells read.** The gavel-arm point toward the hero is the clearest pose in
  every tell sample. Phase 2's gold margin spikes and phase 3's violet halo
  show in the scene at both profiles. The attack pose is readable but less
  distinct from idle than the tell.
- **Facing.** He faces the hero's quadrant in every sample (south-west
  sprites while the hero stands south-west). No heading is mirrored.
- **Grounding.** His feet sit on the contact shadow, with no float or sink.
- **Size (a known limit, not a new defect).** On screen he is about 1.25x
  the hero. The shared contact shadow is sized from his 56 px gameplay body
  (`contactShadowFootprint = 56`), so it is visibly wider than his 60 px
  sprite. That is the clearest sign in the scene that the sprite is smaller
  than the body it represents. The fix is a larger sprite, which needs the
  schema extension (section 10); the shadow is correct.
- **Crown band.** It reads as a thin salmon-pink ring on the dome, and the
  crown spikes are not legible at gameplay zoom. This is left for the owner
  read (gate 2); deepening it is one derivative constant plus one re-render.

The review also found a UI problem outside this branch's scope, for the owner
and a UI slice. At the boss-fight zoom the top HUD panel covers the upper
~190 px at desktop and ~215 CSS px at the phone (about a quarter of the
screen height). The camera also does not frame the boss. A hero standing due
south of the Liquidator, the natural approach from the arena entrance, sees
only his boots (run 1). A camera bias for the boss fight or a compact boss
HUD would fix it.

No art defect needed a regeneration or a re-render. Nothing in the source
model, derivative or atlas changed in the closeout.

## 10. The schema extension that would lift the single-page cap: not done here

The brief allowed this extension "only if small and projection-only". It
would be projection-only, but it is not small:

- `enemyRosterAsset()` returns one `imageUrl` per actor, and
  `createEnemyRosterDisplay` slices frames from one texture. Multiple pages
  need a page index per frame, a texture array in the `main.mjs` loader (the
  `the-liquidator` branch at the roster load site) and the unload path the
  package asks for.
- The packer in `build-hmh-native-roster.py`, the verifier, the adoption
  scripts and `hmh-reboot-production-asset-qa.mjs` all assume one page, and
  three test files pin 840 frames on one page.
- A second 2048 page adds 16 MiB of decoded texture. Section 5.10 says the
  mobile decoded gate comes first, so the extension cannot land without the
  128 px mobile tier.

The package (4.1) assigns this to the Baron slice, and it should be designed
once for both bosses. The pilot ships at 65 world px under the existing
contract.

## 11. Lessons for the roster steps (measured on this pilot)

- **Credits.** The whole actor cost 85 credits: three heads at 5 each, one
  rejected T-pose body at 5, image-to-model 40 and rig 25. An ordinary enemy
  on the 14-bone auto-weight path should cost about 45-50: one or two
  head/body images, one image-to-model, no rig. The pilot spent 85 of the wave's
  2,000 credits. The closeout spent nothing; the account read 5,835 when it
  began and 5,195 at its commit, the 640 difference coming from tasks this
  step did not fire (see the ledger).
- **Time.** About 45 minutes of machine time per actor: source stage,
  derivative, preview, two cold full renders (6 min 47 s for 840 frames at
  192 px), then adoption and QA, plus review. An ordinary enemy renders 280
  frames, about a third of the boss. Plan for the heavy lock separately: in
  this closeout each review run took about 4 minutes, but the waits for the
  shared lock took about 63 and 35 minutes.
- **Tripo rig output.** It delivers weights only: generic bone names, no
  actions, +X facing, a stray bone-shape Icosphere, 4096 textures and
  1.49 M faces. The Blender source stage does all the useful work: bone
  mapping by geometry, decimation to 125k faces, 2048 packed textures,
  facing and scale. Skip `--then rig` for ordinary enemies.
- **Never use the `t_pose` text-to-image template** for a dressed character.
- **Prompts over 1,800 characters are rejected** (no charge). Condense the
  shared STYLE/AVOID blocks; never cut the HEAD block.
- **Browser review.** Reuse `scripts/hmh-liquidator-browser-review.mjs` as
  the pattern:
  - pick the stand-off from the measured camera zoom so the actor clears the HUD;
  - give the unarmed review hero an evasion policy, or it dies before the late states;
  - stop sampling at death;
  - read the crops, not just the telemetry PASS.

  Ordinary enemies can use `rosterPreview=1&rosterCombat=1` with the roster
  offsets instead of the boss debug spawn.
- **Repo budget.** `npm run repo:health:strict` counts the working-tree
  (smudged) size of tracked files. It reads 806 MB against the 350 MB SHIP
  budget on this branch and fails. It fails on the base `9f20cda0` too: the
  base already carries about 524 MB of smudged LFS objects (hero and native
  enemy `.blend` files, reference sheets). This branch adds 17 MB of LFS (the
  GLB; the Liquidator `.blend` replaced one of the same size) and about
  0.45 MB of review evidence. The gate needs a policy decision (exclude LFS
  source models or raise the budget), not a deletion. Until then, record each
  actor's delta.
- **Check size first.** Measure the probe's widest frame (the tell) and the
  packed page before the full render. For this boss, the single-page cap set
  his size, not the art.
